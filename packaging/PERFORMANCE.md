# 有预算的性能与异常测量

这些工具只使用新建的私有测试目录和合成内容，不读取用户压缩包，
不安装程序、不注册 Shell、不修改默认应用，也不填满系统磁盘或全局内存。
它们属于开发验收工具，不是正式发布已通过全部压力测试的承诺。

## 运行

先构建 Release 测试目标；GUI 图片测量还需要匹配的 Qt 运行库。
选择一个不存在的输出目录：

```powershell
.\packaging\test-performance.ps1 `
  -BuildDir build-package `
  -QtDir tools\Qt\6.9.3\msvc2022_64 `
  -OutputDir out\performance-new-run `
  -LargeMiB 128 -SmallFiles 2000 -Iterations 2 -ImageDimension 8000
```

生成 `archives.json`、`images.json` 和 `summary.json`，不会覆盖已有报告。
核心工程未构建 GUI 时只测压缩/解压，摘要明确列出图片场景跳过。
可用内存或私有暂存卷空间不足时返回跳过，不能算作验收成功。

普通 CTest 使用 8 MiB / 128 小文件 / 2048 方形图片的轻量场景。
显式扩大参数可测到 4096 MiB 单文件、最多 100000 个小文件输出及 8000×8000 图片，
但仍受空间、内存、单项 180 秒等守卫约束；参数上限不表示该规模已完成实测。
8000×8000 正好是默认 6400 万像素上限，不修改用户预览设置或提高该上限。

## 场景与验证

- 大文件 ZIP 创建/解压，SHA256 回读；小文件 ZIP 创建/解压，逐项核对内容和数量。
- 已占用的原压缩包拒绝覆盖，核对原文件身份与 SHA256。
- 核心协作取消解压，核对既有目标身份与内容不变。
- 独立进程组内拒绝超预算分配，不通过耗尽整台电脑内存来制造失败。
- 真实 `decodePreviewImage()` 与解码辅助进程，核对尺寸、像素和输入 SHA256。
- 进程组预算下的图片解码失败、超像素头部提前拒绝、截断图片失败。
- 图片解码测量包括接收缓冲与返回 QImage，不包括最终 GUI 显示、QPixmap 或显卡开销。

测试内容都在自己的目录中按文件身份清理。无法安全确认目录状态时保留夹具，
不能删除任意临时目录、恢复目录或用户文件来“清理测试环境”。
断电或强制结束整个测试父进程不保证自动清理其私有夹具。

## 如何读报告

- `elapsed_ms`：测量子进程从恢复执行到主进程退出的时间；不含父进程生成夹具及校验内容的时间。
- `job_cpu_ms` / `job_read_bytes` / `job_write_bytes`：Windows 进程组累计计数；
  I/O 包含管道和缓存传输，不等于实际物理磁盘读写量。
- `root_peak_working_set_sampled_bytes`：主测量进程的工作集采样，不是整组或整机物理内存峰值；
  极短进程可能无法取得有效采样。
- `job_reported_peak_commit_bytes` / `job_process_count`：保留 Windows 原始计数。
  分配拒绝和系统辅助进程可能使峰值或数量高于直觉预期，不能仅凭该计数判定预算失效。
- `configured_job_memory_limit_bytes`：整组及单进程的私有提交内存预算，不是工作集/共享映射的总上限。
  预算有效性由分配拒绝与失败后数据保持测试验证。
- `fixture_before_logical_bytes` / `fixture_after_logical_bytes`：任务前后的逻辑文件大小检查点。
  最大检查点不等于暂存峰值或物理占用；测量期间不扫描目录，以免干扰被测任务。
- `target_sha256` / `helper_sha256`：记录实际使用的程序和引擎/辅助进程，避免混用不同构建结果。

场景串行执行，文件缓存可能已热；两三轮结果不是统计学意义上的完整基准。
比较构建应使用相同参数、同一机器与文件系统，并记录后台负载、缓存和顺序差异。
早期被目录扫描中断的报告不能作为有效性能基准，也不能用来宣称单因素优化幅度。

## 当前优化边界

没有旧文件时不创建无用途的回滚目录，但仍保留恢复记录、源/目标句柄与失败回滚。
事务优先根据固定目录句柄取得卷 GUID，并缓存该句柄对应的卷标识；
不支持 GUID 的文件系统保留卷映射回退，不靠可能重复的卷序列号猜测同卷。
固定目录句柄的卷能力可以复用，
但当前目录状态、写权限和文件身份仍每次检查。
事务工作区最多缓存 64 个、绝对深度不超过 32 的普通目录锁；
其他目录仍逐次锁定，避免海量/超深目录造成无上限句柄驻留。
缓存复用仍检查重解析点和当前写权限，工作区结束前释放缓存，再按身份清理暂存。
操作中的部分输出目录可能暂时无法移动，操作结束后恢复正常。
Job 对象用于资源预算，不是限制任意恶意代码或同用户进程的安全沙箱。

真实 FAT32/exFAT 磁盘满由另一个仅允许一次性 CI 运行的虚拟磁盘脚本验证；
系统级低内存、跨用户持续竞争、断电恢复、真实 RAR 样本及 Win10/Win11 桌面交互仍需专项验收。
